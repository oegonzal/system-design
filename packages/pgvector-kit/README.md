# pgvector-kit

What every store over pgvector in the repository does the same way, and nothing of any store itself: how a collection is named (`collectionName`: store, generation, model made safe for a name, width — a change to any one is a new collection, never a migration) and which table holds it (`tableName`: `vec_` plus the name lower-cased with every character outside `[a-z0-9_]` replaced by `_`, cut to PostgreSQL's 63-byte identifier limit by keeping the first 50 characters and 12 hex characters of the collection's sha256; always quoted where it is interpolated into SQL — two collections that differ only by letter case or by `-` against `_` share one table, which Qdrant did not do, and no such pair exists since each store names its collection from the one configured embedding model), how a vector and a list of texts are written for the database (`vectorLiteral`, bound as `?::vector`; `textArrayLiteral`, bound as `?::text[]`), the executor an adapter runs its SQL through (`SqlExecutor`: `all`, `one`, `run`, `transaction` — the ORM's in the apps, a recorder in a spec), and how a collection's table and indexes are made sure of at boot (`ensureVectorSchema`: the `vector` extension checked first — `VectorExtensionMissing` names `pnpm db:migrate` when it is not there — then every declared `create … if not exists` in order, the list run once more from the start when another process won a create, SQLSTATE `23505` or `42P07`). No dependency: the kit holds no connection and no ORM type.

The placeholder convention is MikroORM's, formatted on the client before the statement is sent: `?` is a quoted value and `??` an identifier. So generated SQL must never contain a literal `?` — the jsonb `?`, `?|` and `?&` operators are out (`(col->>'k') IS NULL` and `@>` instead), and a literal bound as text is cast on its placeholder: `?::vector`, `?::text[]`, `?::jsonb`, `?::uuid[]`.

The spec support — `hashedUnitVector` and `cosine`, the vector math the in-memory fakes rank by, and `recordingExecutor`, an executor over no database that records every call with its bound values, answers from the script a spec hands in, and marks each transaction's `BEGIN`, `COMMIT` or `ROLLBACK` — is `@sysdesign/pgvector-kit/testing`.
