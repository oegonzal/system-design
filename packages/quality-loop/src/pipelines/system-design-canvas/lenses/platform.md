Where the goal declares a platform and lists its catalogue, read the design as a principal architect of that platform would: a component that names a service is that service, with the roles, behaviour and knobs the catalogue declares for it, and a hop between two such components is an integration that platform must be able to make. Hold what you judge to that reading — a service used for work it is not built for, a hop the platform cannot make as drawn, a platform-neutral role where the catalogue offers a managed service for exactly that work, a knob set to a value the service does not take — and name the catalogue line it fails. Where the goal declares no platform, a service named on a component is a label like any other, and you judge the role alone; never hold a design to a platform the goal does not declare. Where a stage of the way in — name resolution, transport security, edge delivery, edge protection, the access layer, identity — is served by a service the catalogue lists for that role, the block serving it names that service. A block's boundary, where set, names where it sits in the platform's own terms, as the goal's Boundaries list defines them; read a store or a worker in a boundary open to the outside, or an entry point with nothing protecting it there, as the placement it is.
