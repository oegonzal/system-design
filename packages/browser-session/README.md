# browser-session

A Playwright program whose every decision is a quality-loop run. It opens Chrome on a persistent, signed-in profile, observes the page in front of it and asks the loop what to do next; the loop's `browser-step` pipeline plans; form fields are answered from recalled facts — through the loop's `form-memory` orchestration, or recalled from a memory space on the memory host and judged by the loop's `field-answer` pipeline, as the `brain` settings choose — and the engine here only executes what nobody objected to, applies the declared rails, and records every step. Nothing in the package names a site: the mission lives in a markdown goal, and the same program runs any goal.

```bash
pnpm browser-session login --profile smoke --url https://duckduckgo.com         # sign in once; the profile keeps the cookies
pnpm browser-session run --goal packages/browser-session/goals/smoke-search.md --profile smoke --max-tasks 1 --max-minutes 5
pnpm browser-session run --goal packages/browser-session/goals/linkedin-easy-apply.md --profile linkedin --max-tasks 2 --max-minutes 45
pnpm browser-session run --goal packages/browser-session/goals/builtin-apply.md --profile builtin --document resume=<path-to-résumé.pdf> --max-tasks 4 --max-minutes 90   # listing → job tab → employer's form tab; a unit's tabs close with it; --document supplies the file for each document the mission declares under Documents, by name
pnpm browser-session sessions [--limit 20] [--json]
pnpm browser-session show <id> [--json]
pnpm browser-session replay-events <id>    # a recorded session's events again, for a record that missed them
pnpm browser-session teach-again --sessions static/sessions --subject "Your Name" [--tenant verify-<stamp>] [--dry-run]   # the recorded operator answers taught again in today's shape through the brain the settings choose — under the tenant named, else the environment's — each answer its own receipt and its row linked to its own record; an older answer is taught in the unit of work its dump records open at its step, under the scope the digest of its earlier teaching gave its question while the loop still holds that run; under the loop brain their earlier digests are retracted once the new facts stand whole; an answer on a channel the operator settings' `untaught` names is counted and left as it was
pnpm browser-session replay-fields --sessions static/sessions --tenant verify-<stamp> [--sample n] [--judge] [--retract n] [--out static/replays]   # every recorded form page recalled for again through the shipping memory recall (brain `memory`), under the tenant named, and compared with the evidence its recorded run was given — each cited text found by three declared rules read apart (the same words, the question's identity, the fact's words contained) or missing, new items, unit and tenant leaks read off the scope the recall answered each record under, recall latency beside the recorded recall step's; with --judge the pages are judged again under the replay's own id and routed by the shipped answering settings, each field given a verdict against the operator's answer on record for its unit (`--sample n` draws n such fields across the dumps); with --retract n that many recalled records are closed in the tenant replayed against — a verification tenant's — and recalled for again; rows.csv and report.json under <out>/<stamp>; no row, no dump, no teaching
pnpm exec nx test browser-session          # pure, browser (headless bundled Chromium) and db projects
```

Exit codes: a session that ended `complete` or `stopped` is 0, `failed` is 1, a usage or configuration problem is 2.

Rails (`--max-tasks`, `--max-minutes`, `--max-failures`, `--max-stalled-steps` over the session file's values; brain faults in a row and unreadable pages in a row only from the file) are the engine's only decisions of its own that end a session; its one other decision of its own, the record check at `taskStart`, refuses one action and counts a failed step, and ends nothing. Each rail is a limit and ends the session `stopped` — save unreadable pages inside a unit of work, which end that unit `failed` and close its pages, the session going on from the page the unit was taken from; the one goal among them, `--target-done n`, ends it `complete` once n units of work have closed `done` — counted on that outcome alone, and refused at start when it is above `--max-tasks`, since a done unit spends that budget too. Time is the one rail that also refuses an action: once `--max-minutes` have elapsed no unit of work starts (a `taskStart` then stops its plan, counting nothing), and a unit open when they elapse may finish within the session file's `unitGraceMinutes` (70 shipped, sized from the units measured to their close; 0 ends the session at the limit whatever is open) — the session ends `max-minutes` once no unit is open past the limit or when the grace runs out, and a question waiting on the operator is withdrawn at the limit only when no unit is open, at the grace's end whatever is. Whether the browser shows is the session file's choice; `--headed` or `--headless` decides for one run.

A session whose process stops beating without closing it — killed, crashed, the machine put to sleep — would read `running` for good. The next session to start closes every such row as `failed` and `interrupted`, finished at its last beat, and says how many; a session alive beside it beats every 15 seconds and is never touched, and a close that later arrives from the stopped process overwrites the row with what ended it.

## How a step goes

1. Observe: the accessibility snapshot (`ariaSnapshot({ mode: 'ai' })`) gives every element a ref; the DOM facts behind each interactive one — type, value, the options a person can answer with (never one the page disables, nor a required select's placeholder, and a select resting on either holds nothing), required, disabled, visible, maxLength, the hidden traits that mark a field a person could never see, whether the page marks it invalid, how many options a long select offers past the ones listed, and whether a modal dialog encloses it — are read in the page. An element is offscreen only when no scrolling of the page or of any box inside it could show it: a footer past the fold of a dialog that scrolls is reachable, an input parked off the page is not. A ref resolves only within the observation that minted it. The page is reported only once two reads in a row agree on every fact the goal renders, so a control that renders a moment after the document is seen. An element the tree gives no name carries the words a person reads on it as `text`. The modal dialog in front, when one is open, is the observation's active scope: the goal lists what is inside it first and counts the rest as behind it. A snapshot too large for the observation's bound is reduced by declared rungs (`SNAPSHOT_RUNGS`) — the open dialog whole and the rest reduced, the lines that carry words, those words cut where the room ends with the rest counted, none — and never to wordless lines; the observation and the plan record which rung the model read at.
2. Plan: first each advisor the mission names is asked what is on record of units beyond this session (`POST /advice`, every step — the next item is chosen inside the plan that closes the unit); an advisor that faults is said once and its last good advice used, probed once a step, until it answers again. Then the goal (mission, page, elements, snapshot, recent actions, units of work — the units on record among them, by stance — limits, index) is composed within the loop's budget by a declared ladder — full, without the snapshot, with element context trimmed, with fewer elements (counted) — and run through `browser-step` with the rubric derived once per session. What runs is read back from the run (`routePlan`), never judged again: a plan a blocker names as a whole runs nothing; one a blocker or validator cut at a position runs up to it; one nothing cut runs whole, whatever its score — only a plan carrying an action that ends the session, or one the evidence gate found under-judged, is held to the accept bar. The validators refuse, from that action on, a ref the page did not list, a touch on a disabled, hidden, not-visible or behind-the-dialog element, anything after an action that replaces the page, and a `taskStart`, `taskDone` or `terminate` after any action that could have changed the page — a claim rests on the page as observed; a unit opens for the item this page shows. An action the page refuses — a click or a field fill — stops the plan there and counts one failed step toward `--max-failures`; so does a plan the loop handed back. A redundant `taskStart` or `taskDone` is recorded and skipped, never a reason to refuse the plan. A `taskStart` at a unit the record refuses — on record as forbidden, or on record to avoid unless the mission declares the exception (`## Taking a unit on record`) and the plan declares `onRecordTaken: true` — opens nothing, stops the plan there and counts one failed step, and the next goal carries why: the history keeps the fact, an objection carries the reason once; the session checks every unit the advisors answered, not only the ones the goal had room to list, and the validators cut a declaration the mission never granted or that this page withholds. The loop is asked for a second iteration only on a page unchanged since the last plan when that plan ran nothing: then the engine's own briefing is all there is to answer, and otherwise a fresh plan is briefed by what ran. What did not run is told to the next plan as `not-executed`, with why, and its `## Page` says what led to the page — the action that ran, and what the plan held past it for this page.
3. Fields: `askFields` sends the fields to the brain — under the memory brain one `field-answer` run over evidence recalled from the space; under the loop brain, until the cutover, the `form-memory` orchestration — with what each holds now — except those that still hold what this session settled for them in the same unit of work, which are kept without a run — and the open unit of work by its key (`unitKeyOf`: the identity its mission declares, or the task row's own id when it declares none), which the goal's index names so the recall reads, of what was recorded for one unit, only that unit's — and with what the page stated about the unit when it opened, under the goal's `## Open unit of work`, so a question about the unit itself is answered from the unit's own words. Each answer is routed by declared precedence — the page's own hidden traits, an admission that says nothing was judged, what a judge or validator pointed at, then the model's decision with its confidence and basis — to fill, keep, leave blank, or ask the operator, who is asked only about a required field — one the page's markup requires, or one this session left blank in the unit of work and the plan asks again, since the page would not go on without it. A field chosen from takes its answer by `select` — a control typed into and chosen from (an input with the combobox role) included: the select clears the words an earlier attempt left, types the option's words key by key — a list that opens on a key and never on words set whole opens for them — and chooses, from the lists the control names, the option whose words are exactly those within the observe settings' `optionWaitMs` — clicked by its words, never its place — and otherwise, when the control names a list, fails naming what it offered for those words, while a control naming no list keeps the words typed; a radio group — one the page declares by role, or radios it groups by name alone in a box that holds that group and no other control, as checkboxes sharing a name are read too (`name-groups.ts`) — offers as its options the words a person reads on each — its own, else its name, else, when every option is named after the question, those of its row (the words after it in a flat layout, its column's header in a grid), never words the page hides, announces apart or uses to describe it — and its select chooses among the options the observation offers, refuses words two options share, and clicks where a person's click on the option lands inside its own row — the radio itself, its labels, the box drawn around it, the marks beside it, its row, its words — in turn until the group reads it as chosen, read back within `optionWaitMs`, or fails without a click when no such point shows (`radio-group.ts`, `radio-choice.ts`); a checkbox its page drew over an input with no box of its own, which the tree gives no ref, is listed under the box that holds it alone, and a click on it turns it the other way where a person's click on it lands, one point at a time until it reads turned; a `fill` only types. A fill the page refuses stops the fields after it, which are not attempted, and the history note names the refused field and why — except the operator's own answer, which is first put back to them with why, so they can choose again or fix the field in the browser and have it read back. An operator's answer is taught back the moment it is given: under the memory brain as one fact of the subject's in the space, the record id landing on the decision row (`teaching_ref`); under the loop brain, until the cutover, as one guidance document (`document-memory`) naming the unit it was given in, whose orchestration id landed on the row.
4. Progress: a progress criterion the evaluator passed is settled once the next observation shows the page moved — every pass when the plan ran whole, else the passes an action that ran said it served (each action may name the criteria it serves) — for the session when no unit of work was open, for the unit otherwise. A session-settled criterion leaves the rubric later runs are judged against and is carried in the goal's `## Progress` section with its statement; a unit's are listed by id, still graded, and cleared when the unit closes.
5. Units of work: `taskStart`/`taskDone` open and close `browser_task` rows. A `taskStart` carries the facts the mission declares under `## Unit identity` (`- <name>: <what it means on the page>`) as facets, each value as the page names it: the row stores them, the goal renders them beside each open and closed unit, and the loop's limits validator cuts a `taskStart` that lacks a declared fact, names one the mission does not declare, names one twice, names a unit an advisor has on record as forbidden, or declares `onRecordTaken: true` where the mission declares no exception or this page lists the control the mission ties it to; the session then holds the `taskStart` to the whole record it was composed with (`refusedOnRecord`, every unit the advisors answered): a forbidden unit is refused all the same, and one on record to avoid is refused unless the mission's `## Taking a unit on record` declares the exception and the plan declares `onRecordTaken: true`. A `taskStart` also captures what the page states about the unit — each node's words inside the landmark the mission declares under `## Unit context` (`- landmark: <role>`, one of the page's top-level ARIA landmarks; a landmark nested in it is its own), read from the observation the unit opens on, within `UNIT_CONTEXT_MAX_BYTES`, cut at a node boundary with the lines left out counted — which the open unit carries to the answerer and `02-tasks.json` records; a mission that declares none carries none, and no row or bus event carries it. Each open and close is also said on the notifications bus — `session.unit.opened`, `session.unit.closed`, beside `session.started` and `session.ended` — with the row's own id, the unit's facets and the session's lifetime as `maxMinutes` — its time limit and its unit grace together, for whoever keeps a record beyond the session; the events ride a queue of their own, so a bus riding out a restart never holds a row behind them. A unit's pages close with it: after the plan in which a unit closes, whatever its outcome, the session closes every page opened since it opened or since the last such close, newest first — a page the site itself closed is not counted, the last page open never closed — brings the newest page kept to the front, drops the last action's promise about a page now gone, and tells the next plan in its recent actions how many pages closed and which page is in front; a session whose units open no page sees nothing.
6. Rails are checked after every step; a plan's `terminate` ends the session on a stop its mission declares under `## Stop conditions` (`- <cause> (<ending>) ["<words the page shows>"]: <meaning>`): the row records `mission-stop` and the mission's cause word, in the status (`complete` or `stopped`) the mission declares for it. The page-stalled rail counts observations in a row of a page that did not change, whether the steps between them were refused, failed, or ran and moved nothing.

## The operator prompt

When a field needs a person the field is highlighted in Chrome and the question goes to every operator channel at once — the terminal always, and the notifications service when the `operator` settings add it, which puts it on its own channels (Telegram among them). Every channel shows it the one way the notifications contracts describe — options lettered, the answerer's untrusted pick marked with why, the commands — and reads a reply with the contracts' `readReply`, so `b` means the same at the terminal as on a phone. At the terminal:

```
──── operator needed ────
Work authorisation
select, required
Are you authorised to work in this country?
Page: Apply — additional questions
Unit of work: Senior Engineer at Acme
Suggested: "Yes" — not filled: rests inferred: a guess

  a) Yes   (the answerer's pick — not filled: rests inferred: a guess)
  b) No

  /readback  I filled it in the browser: read it back   (Enter alone)
  /blank     Leave it empty
  /stop      End the session
Reply with a letter (a, b) or the option as written, or /readback, /blank, /stop.
>
```

The first answer is taken (`src/core/first-answer.ts`); every other channel is withdrawn and says who answered and what. The answer is filled — the full value behind a choice — recorded with `source: operator` and, in its payload, the channel it came on (`via`) and what it was chosen from (`chosen`: an option, the answerer's value, a suggestion by what it rests on, or typed), cached for the unit of work it was given in by what the field asks — a later form of that unit, or of one with the same declared identity, takes it without asking, and another unit's asks again — and, unless its channel is one the operator settings' `untaught` names, taught back at once, the taught section naming the channel beside where and when it was asked and the options it was chosen among; an answer on a channel named there is kept for the session alone and the step says so. A line typed at the terminal while no question is open is said to be unused, never kept for the next question. Ctrl-C ends the session as the operator's word, after the step in flight and through every closing write — the row closed, the events out — rather than killing it with a running row behind, and no unit of work starts in that step: a taskStart planned while the stop came is not run, nor anything after it; a second Ctrl-C exits at once.

A field with no options going to the operator also gets suggested answers (`src/core/operator-ask.ts`). Once a form's fields are routed, one `answer-suggestions` run is opened for every such field (through `form-memory` under the loop brain, directly under the memory brain), under the session's own derived rubric, and never waited on: the question goes out at once. When the suggestions arrive before an answer the question is withdrawn as superseded and asked again with them; an answer given first is taken. They are lettered record first, then the drafts labelled apart — `draft: transferable`, built from recorded adjacent work, and `draft: invented — not in your record` — less every one the run's report withholds, and none from a run no judge saw. The mission's `## Suggesting policy` says when drafts are drafted at all; the answering settings' `drafts` table says which bases are typed in the operator's place rather than offered — by the shipped file, every one that exists, the withdrawal saying what was filled and what it rests on — so a lettered draft reaches the operator only for a basis set to `offer`. A chosen letter fills its whole text and is cached and taught like any answer.

## The dump

`static/sessions/<dump run id>/` — `manifest.json` (the settings files in force among it, and the events still unsent when the close stopped waiting), `goal.md`, `01-steps/NN/{observation.json, snapshot.txt, screenshot.png, advice.json, plan.json | fault.json, fields.json, teach.json, captures.json, captures/MM-<kind>-<what it touched>.png}`, `02-tasks.json` — each unit's row beside what the page stated about it when it opened; `advice.json` records what each advisor said for the step — answered or stale, from which step, how many units and how many omitted — and the units the goal was composed with; `fields.json` records what became of the form's suggestions — `pending` when the form was settled before they came, else the run, its admission, what it withheld and what was offered, or its fault; every image is the page at CSS scale, and a capture's file name never carries the value entered — `captures.json` lists each image with the action that made it; one row in `static/sessions/index.jsonl` once the session is whole. `plan.json` records which rung of the goal ladder the step used.

## Records

Three tables in `packages/db`: `browser_session`, `browser_task`, `browser_decision`. A session row carries `subject`, whom it acted for; a task row carries `facets`, the unit's declared identity. Loop ids on a decision are plain columns, not foreign keys — the loop is another service. `pnpm browser-session replay-events <id>` publishes a recorded session's events again from these rows, for a record that missed them; a consumer keyed on the unit's id takes a replay as nothing new. A `running` session whose `heartbeat_at` is older than 60 s belongs to a dead process.

Learning queries:

```sql
-- Ask rate per session over time: how often a field needed a person.
select s.started_at::date as day, s.id,
       count(*) filter (where d.kind = 'field-answer') as fields,
       count(*) filter (where d.kind = 'field-answer' and d.source = 'operator') as asked
  from browser_session s join browser_decision d on d.session_id = s.id
 group by 1, 2 order by 1, 2;

-- Fields first asked of the operator, then later answered from memory: the join is the exact question.
select asked.question, min(asked.created_at) as first_asked, min(learned.created_at) as first_from_memory
  from browser_decision asked
  join browser_decision learned on learned.question = asked.question
   and learned.source = 'memory' and learned.created_at > asked.created_at
 where asked.kind = 'field-answer' and asked.source = 'operator'
 group by asked.question order by first_asked;
```

## Layout

`src/core` (pure: ports, the engine, step execution, the field flow, rails, the write queue and heartbeat, the advisors and the session events, the dump layout, the fakes), `src/adapters/{playwright,loop-http,memory-loop,advisor-http,mikro-orm,terminal-operator,notifications-http,fs-goal}`, `src/modules/{app,session}` (the composition root), `src/cli.ts` + `src/render.ts`, `goals/`.

## A record beyond the session

A mission may declare what identifies a unit of work beyond this session and who keeps the record:

```markdown
## Unit identity

- company: the company as the listing's pane names it, beside the title.

## Advisors

- record

## Taking a unit on record

- avoid unless "Next": only when no next page is listed may a unit on record to avoid be taken.
```

The convention, so the next domain follows it rather than inventing one: a declared mission section → a field in the goal's index → a rule in the loop's limits validator → a line in the goal's Limits → a rendering beside the thing it is about → the engine's own check at `taskStart` against the whole record the step was composed with, whatever the goal had room to list → a port for what the goal cannot carry → a bus topic for what happened. A section that only tells the answerer something, as `## Unit context` below does, follows the shorter chain: a declared mission section → a port for what the goal cannot carry → a rendering beside the thing it is about → the dump — no index field, no validator rule, no topic. An advisor is any service that answers two routes with the contracts' shapes — `GET /advisor` with who it is and which declared facets it keeps its record by, `POST /advice` with the units on record for a subject, each by identity, with a stance (`avoid`: prefer another item; the session refuses a `taskStart` at one unless the mission's `## Taking a unit on record` declares the exception — `- <stance> unless "<control the page lists>": <meaning>`, or `- <stance>: <meaning>` for one tied to no control — and the plan declares `onRecordTaken: true`, a declaration the validator cuts while the page lists that control; `forbid`: never started, the validator cuts a `taskStart` naming one and the session refuses it all the same) and a note — and subscribes to the session's topics to keep that record. The session names no domain: the mission says which advisors, `UNIT_ADVISOR_URLS` says where, the advisor says who it is. The walk-through, with the job-application record as the first tenant: `docs/quality-loop/domain-rules.md`.

## What a unit states about itself

A mission may name the landmark whose words are a unit's own statement of itself:

```markdown
## Unit context

- landmark: main
```

As a `taskStart` runs, the engine takes every node inside that landmark from the observation the unit opens on — each node's name and inline text, in document order; a landmark nested in it (a navigation, a complementary overlay) is its own and stays out, the one reading of "inside" the engine has (`ancestryOf`) — up to `UNIT_CONTEXT_MAX_BYTES`, cut at a node boundary, the node lines left out counted (`UnitContext.omitted`). The open unit carries it to the answerer under the form goal's `## Open unit of work`, titled by the landmark it was read from and by how many of its nodes the goal shows, where a question about the unit itself is answered from the page's own words — a value resting on them alone declares the kind `unit`, which `config/answering/standard.json` fills — rather than refused for want of evidence. The form goal is fitted to the loop's budget by a ladder of its own (`composeFieldGoalWithinBudget`: the statement whole, cut to the room the mission and the fields leave, or dropped with a line saying so; `fields.json` records the rung), and the recall then fills what room remains with evidence. The landmark is one of the page's top-level ARIA landmarks (`LANDMARK_ROLES`): a role the vocabulary does not name refuses the session before it has a row, a mission that declares none carries no statement, and a page that lays out no such landmark carries none either. `02-tasks.json` records the statement beside each unit — `{ landmark, text, omitted }`; no row and no bus event carries it. Measured 2026-10-14 on the shipped mission's layout, the declared landmark also holds the page's list of other items ahead of the unit's own description, and no finer seam the page declares — a role, a name, a listed element — bounds the description alone; so the statement is the landmark's, the title over it says it may name other items beside the unit, every lens reads what it says of another item as no statement about this one, and the bound is sized above the largest recorded page rather than to the description alone.

## Documents the planner may upload

A mission may name the files a plan may put into a file control, and nothing else is ever uploaded:

```markdown
## Documents

- resume: the applicant's résumé, a PDF
```

The chain is the convention's: a declared section → the goal's index lists the names (`documents`) → the loop's limits validator cuts an `upload` naming a document the mission does not declare, or aimed at an element that is no file control, while a `fill` or an `askFields` on a file control stays a wrong-kind cut → a line in the goal's Limits says so → the file control is rendered beside what the page shows (`type file`), listed whether or not the page shows it → the session's own check at boot: the run supplies each declared document as a file by name (`--document <name>=<path>`, once per document), and a declared document with no file, a file that is not there, a supplied file no section declares, or a name supplied twice refuses the session before it has a row → the browser port takes the files by name at `open` and an `upload` puts one into the control with Playwright's file setter, which needs no sight. A file control is routinely hidden behind the page's own attach button, drop zone or label — on every form measured, the one way a résumé is attached — and a hidden input has no node in the accessibility tree and so no ref of Playwright's; the adapter lists each hidden `input[type="file"]` as an element of its own under a ref of the adapter's (`f1`, `f2`…) that resolves to that control, with its label, what it accepts, where it sits and whether it is disabled; one the page shows is read through the tree like any control. The effects table (`ACTION_EFFECTS`) declares `upload` the one action that needs no sight, so the validator holds it to a control's disabled, dialog and mark rules and not to its visibility. The history and the images name the document, never its path; the next goal reads `upload "resume" into button "Attach résumé"`. A mission that declares no document makes every upload a cut.
